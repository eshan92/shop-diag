## 2026-08-26 — the non-security backlog

Eshan asked to skip security and clear the rest. Four items done, each proved
failing first, then passing, then deployed with same-minute backups.

### E14 + E13 + E21 — `add_sale()` cleaned up

All three lived in the same function, so they were done together:

- **E14** — the "not enough stock" and bad-batch paths returned straight out of the
  `try` without closing the connection or rolling back. Now every early exit rolls
  back, and `conn.close()` moved to a `finally`.
- **E13** — `fifo_consume` was wrapped in `except Exception: _cost = buy_price * qty`.
  If it ever threw, the sale still saved with average cost instead of the real FIFO
  cost — wrong COGS, silently, with no log. The wrapper is gone: a failure now rolls
  the whole sale back and returns an error.
- **E21** — the pmode path ran `stock +qty` immediately after `consume_batch` had
  done `stock -qty`, then a shared `stock -qty` at the end. Net result was right but
  the `+qty` read like a bug and anyone "tidying" it would have broken stock. The
  decrement now happens once, in the FIFO branch only, where it belongs.

### E18 — Add Lot folded into one request

Same shape as the Add Stock bug: money.js fired `/api/bank/purchase` 700 ms after
the lot POST, outside the transaction, with `.catch(function(){})`. It happened to
work because its element ids were right — Add Stock's were not, which is how that
one hid for weeks.

`/api/lots` now takes `source` and writes the lot **and** the purchase row in one
transaction, with rollback. The money.js follow-up call was removed, not repaired —
repairing it would double-count every lot purchase. Verified in a browser that the
payload carries `source:"owner"` when My Money is selected; nothing was submitted.

### E11 — expenses can finally be corrected

`expenses` had no `status`/`void_reason`, so a wrong one could only be fixed by
editing it in place, which rule 2 forbids. Added the columns plus `by_user`
(guarded — `shop_bank` is imported before `init_db()` creates tables, so the
migration skips rather than crashes if `expenses` does not exist yet).

New `/api/bank/expvoid`, mirroring `depvoid`: reason required, no double-void,
cashiers limited to today, audit log entry, Telegram notice. Admin expense list now
shows a Void button, and voided rows appear struck through with their reason.

The risky half was not the void — it was that expenses are summed in **seven**
places. All seven now exclude voided rows: `shop_ledger` (×2), `shop_bank`,
`shop_report`, `shop_growth` (×2) and `server.py` (×2, including the 9PM Telegram
report). The test checks each one: void a Rs.700 expense against a Rs.300 live one
and every total must read 300, with cash rising by exactly 700.
